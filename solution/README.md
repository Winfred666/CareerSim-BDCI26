# CareerSim solution

入口：`skills/observe-decide-review/SKILL.md`。

Leader 执行必要初始化、观察、行动和复核；指标问卷交给五名原生 teammate，不另设 handbook 阶段。read-context 使用公开状态、月份和已执行动作记录，保留 H≤3、D≤3、W≤2 时禁止削减对应指标的规则，以及原有 R 风险判断。半年考核前检查谈话、绩效与完整晋升门槛；季度阶段枚举最多三次体力行动与一次主行动的组合，执行后重新规划；最后一个月按官方量化计分公式选择收益。普通推荐只返回 `{"推荐选项":编号,"notes":"简短理由"}`，Leader 机械采用编号并原样填写 notes。纠偏包只返回原题、前情、原始选项及仅按当前状态计算的 constraints；不返回预测增量、推荐、排名、净值、脚本 notes 或任何当前事件选项偏好。Leader 独立判断原题并自行填写一句行为理由。阶段记录与校验由脚本完成。

策略位于 `scripts/numeric-policy.py`，仅依赖标准 Python 与原有红线函数。普通事件先执行 H/D/W 禁减；考核前检查存活与完整晋升可行性，再在候选内沿用 R 风险优先级。净值以官方量化增量为基础，使用封顶、保底、职级缩放后的真实差值：封顶的 SONH 正增量价值为0；晋升表最大缺口每点追加6，其余缺口每点追加3，满足门槛后的正向储备仅追加0.25。未全部达标时，进一步扩大缺口每点追加扣6；全部达标时跌破门槛每点追加扣3。SON全部达标且距下一次评审1月时，SON任何实际下降每点追加扣4。有效R下降每点收益1.5，有效R上升每点扣6，替代官方计分中可能封顶的R项；R++按实际增量扣分，例如有效R+2扣12，不再单凭原始R增量≥2硬排除，实际预测淘汰仍触发纠偏。第47月起，H实际增减的价值由0.75放大到0.9375；第48月不再追加晋升或储备价值。

安全候选均无有效正增益时按上述实际净值选择最小损失，不追加普通缺口或储备奖励；考核前或当前SON全部达标时，把下一次公开考核结算纳入净值，避免为眼前少扣分破坏已获得的晋升机会。已满足 SON 的评审前候选先比较完整晋升，绩效超过本级晋升门槛后不继续压过净值。季度规划逐步遵守禁减约束，比较整个组合的终态风险和晋升缺口；第42月起、L5及以上，结合下一次考核结算比较官方量化收益；第45月已预测通过最后一次晋升时，不再为后续晋升追加绩效投入。月份、任职时长与体力来自公开 observe，动作计数来自本局已完成的 action 记录；R 以月度 HR 提示为起点，累计本月已选动作的 R 翻译，并用公开日志处理爆雷重置。没有读取未来剧情、模拟器内部计数或隐藏统计，也不新增 D 问卷：D 使用公开现值和固定行动的官方增量。

`scripts/translation-errors.json` 从 `logs/conditional_model.json` 和 `logs/conditional.py` 导出 O/N/S/W/H 的条件误差分布，记录两个源文件的 SHA256。误差定义为“实际名义增量−预测增量”，当前问卷版本没有对应校准样本，使用原模型的 prediction + metric 回退。`translation-error.py` 对原规则得到完全相同预测终态、且 R 原始增量相同的候选，比较守住 SON 门槛的概率，再比较官方量化期望收益；误差层不改写原始输入符号。

普通事件先用32组固定分层整数误差情景检查推荐的稳定率，支持率在0.375至0.625之间时改用128组提高阈值附近的精度。采样序列按指标向量规范排序分配，原题、事件ID、选项编号及展示顺序不参与不同指标向量的序列分配。每组继续执行原红线、季度和考核规则；原推荐属于策略并列最优时也计为支持，排除编号平局的影响。整个事件所有选项的原始S/O/N/H/D/W均没有正增量、R均没有负增量时，判为纯负面翻译，触发裸事件纠偏；R下降算正向收益。正向预测因封顶而没有实际增益不会触发这条规则。纯负面、预测淘汰或原有L1门槛死局的情景不计为支持推荐。结构死局及所有候选预测淘汰直接记为可信度0；其余推荐的最终情景支持率低于0.5时，也返回原题、前情和原始选项，让 Leader 走已有裸事件判断流程，不返回推荐编号或带误差的指标。可信度0表示符号策略放弃直接推荐，不能解释为真实选项一定有害。固定官方增量不加误差，同一输入给出相同结果，不读取运行时 logs 模型文件。

此可信度是指定边际误差模型下的决策稳定率，未校准为真实比赛正确率；R、普通事件D及未来剧情不在该误差模型内。模型历史版本与当前问卷不同，也没有各指标、各选项间的联合误差分布。阈值用于触发语义纠偏，不会降低 H/D/W 禁减约束或重排风险优先级。

仓库的 `scripts/benchmark_symbolic_policy.py` 可离线将该误差模型采样到普通事件的决策输入，实际行动仍按官方模拟器结算。支持历史预测频率、均匀预测频率及手动扣除误差三种模式，报告量化原分、折算分、完成率和需要语义介入的次数。`--workers 4 --no-confidence-diagnostics` 并行跑分并跳过不影响行动的可信度统计；正式脚本的可信度机制保持启用。默认仍采集可信度，快速模式的纠偏计数不可用于估计纠偏概率。`--context-script` 可指定冻结的旧版红线及辅助逻辑，保证配对比较使用完整旧基线。`--start-index` 可用新种子扩展同一组测试。每局均新建官方引擎、会话和存储，仅在工作进程内复用加载后的官方事件和规则；`--fresh-resources` 每局重新加载，可核对动作、状态和分数一致性。`scripts/compare_symbolic_scores.py` 报告精确二项顺序统计的中位数95%区间及配对种子 bootstrap 的差值区间；统计重采样不选择事件或拟合策略。它隔离测试符号策略，未运行 Player 或云端评审；R 和封顶值准确、普通D省略、指标误差独立是测试假设。

初始化先调用一次 skill_tool 获取技能目录和内容，再新建游戏，将 session_id 交给 workflow-state.py create_new；脚本从自身路径确定工作目录并展开运行时 Markdown 占位符，提示 Leader 仅重读 SKILL.md 后继续第 2 步。身份校验复用 workflow-state.json，不使用 session.json。
